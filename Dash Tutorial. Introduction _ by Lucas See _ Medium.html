Write Sign in Dash Tutorial Lucas See Lucas See 11 min read · Nov 28, 2023 Introduction At a certain point in the data science project lifecycle, you will need to share your work with others. While there are many options for this one of the easiest native Python methods is Dash. Dash is a Python library built on Flask and React that allows for the development of interactive data applications. The key selling point of Dash is you can do all of your work in Python without learning any additional languages and can still create beautiful, functional applications. In this tutorial, we’ll walk through an in-depth example covering many of the core components that Dash has to offer. I've included a broad set of components in this project so by the end we’ll have a beautiful dashboard shown below that you can adapt for your own applications. If you just want the code for this project without the tutorial you can find it on GitHub below. We can start by importing these libraries: from dash import Dash, dcc, html, callback,Input, Output,dash_table import dash_bootstrap_components as dbc import plotly.express as px import pandas as pd import os import numpy as np #For modeling from sklearn.metrics import confusion_matrix from sklearn.ensemble import RandomForestClassifier from sklearn.model_selection import train_test_split Data After installing dash and importing libraries the next step is getingt the data we’re going to visualize. In this project the primary dataset we’ll be using is a heart failure prediction dataset found on Kaggle here: https://www.kaggle.com/datasets/andrewmvd/heart-failure-clinical-data?select=heart_failure_clinical_records_dataset.csv The dataset contains medical data such as blood pressure, age, and weight for different patients and then a response variable DEATH_EVENT which captures if the patient died of a cardiovascular event. base_path = os.path.dirname(__file__) file_name = 'heart_failure_clinical_records_dataset.csv' total_path = base_path + '\\Data\\' + file_name df1 = pd.read_csv(total_path) In addition to visualizing the underlying data we also want to generate a basic model predicting Death Events based on the 12 independent variables. To do this we define a basic train_model function as shown below that splits our Dataframe into an X and Y set, splits further into a 25%/75% test/train set, fits a Random Forest Classifier on the train set, and then evaluates on the test set. The function then returns two variables; a 2d numpy array containing a confusion matrix(https://en.wikipedia.org/wiki/Confusion_matrix) generated by evaluating on the test set and the model itself. def train_model(df): X, y = df.drop(columns = ['DEATH_EVENT']), df['DEATH_EVENT'] X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42) #Training clf = RandomForestClassifier(max_depth=2, random_state=0) clf.fit(X_train, y_train) #Predicting and making confusion matrix y_pred = clf.predict(X_test) cmatrix = confusion_matrix(y_test, y_pred) return cmatrix, clf #Training model and retunring datasets cmatrix, model = train_model(df1) X_cols = df1.drop(columns = 'DEATH_EVENT') App Definition Next, we’ll initialize the app, define the layout, and the style of our app. This is all shown below, the key piece to notice is that the html.Div() components act essentially as buckets holding individual pieces of our application. Once our initial html.Div() bucket is defined we then structure an array of children components inside this bucket, including other html.Div() components, which allows us to build up the layered structure of our application. While the below structure may look complicated it's really only made of a couple of components that we’ll now walk through. Prior to defining it, we create a SIDEBAR_STYLE dictionary that defines how the sidebar will render. The second component we define is the header and filter component that are shown on the top of the final dashboard. There are a couple important things to note in the below structure: Filters are made up of alternating html.Label components to describe the filter and dcc.Dropdowns to implement the filter Each Dropdown gets a distinct “id” component that will be used to pass user inputs to callback functions to update our graphs The Dropdown “options” input contains a mapping of labels displayed to the user to values those labels map to. We want to ensure all distinct values are available for filtering as well as an “All” option that can be passed to the callback to return all values We default to this “all_values” option by setting value = “all_values” For styling we only set the width to 30% of the available space so the dropdowns don't stretch across the entire screen FILTER_STYLE = {"width": "30%"} filters = html.Div([ dbc.Row([ html.Div(children= [ html.H1('Heart Failure Prediction'), dcc.Markdown('A comprehensive tool for examining factors impacting heart failure'), html.Label('Blood Pressure'), dcc.Dropdown( id = 'BP-Filter', options = [{"label": i, "value": i} for i in df1['high_blood_pressure'].drop_duplicates()] + [{"label": "Select All", "value": "all_values"}], value = "all_values"), html.Label('Sex'), dcc.Dropdown( id = 'Sex-Filter', options = [{"label": i, "value": i} for i in df1['sex'].drop_duplicates()] + [{"label": "Select All", "value": "all_values"}], value = "all_values"), html.Label('Anaemia'), dcc.Dropdown( id = 'Anaemia-Filter', options = [{"label": i, "value": i} for i in df1['anaemia'].drop_duplicates()] + [{"label": "Select All", "value": "all_values"}], value = "all_values")]) ]) ], style = FILTER_STYLE) After defining the Header and filters if we then run the app as shown below with only the sidebar and filters we get exactly that: #Test Lines to show dashboard with only sidebar +Filter components, not used #in final product app.layout = html.Div(children = [ sidebar, html.Div([ filters ],style = CONTENT_STYLE) ]) app.run_server() Press enter or click to view image in full size Text Card: The third component we need to define is the text card which clearly displays summary information on our dataframe including the number of rows, number of deaths, and number of survivals. First, we define a draw_Text function shown below that takes a specified string and returns an html.Div component containing a card and card component for displaying the text. Next, we need to define a callback function that calls our draw_Text function and returns a row of 3 text cards. This callback function is shown below and is triggered whenever any of the input items are interacted with by the user. The 3 filter id’s shown here match the id’s assigned to the filter objects meaning whenever one of them is called the callback will be triggered. One critical piece to note is the return type of our callback isnt a figure but rather a row object with the type component_property = “children”. While we could have made a different callback for each of the 3 text box’s its more space efficient to define one callback and return a row containing the 3 text boxes. To achieve this we take a similar approach as with the previous text card; we define a function to render a single graph, define 2 callback functions(one for the first row of graphs and one for the second), and then define two rows in the app layout that are updated by the callback functions. The reason we went with two callbacks instead of one is that the top row works with the basic dataframe while the bottom row uses the confusion matrix so we decided to break them apart. Starting with the first function below we define the draw_Image function to take an input fig, create an html.Div object with a card + cardbody in it, and then render the image as a dcc.Graph on the CardBody. This is the same approach taken with the draw_Text function except we are using an image instead of text. Next, we have our two callback functions, both of these take filter inputs and return a row output with distinct component_id’s (One is ‘EDA-Row’ and one ‘ML-Row’). In both functions we perform data filtering based on user inputs, generate figures, place these figures in a row, and then return the row. Like our previous callback function, the structure of our output is a dbc.Row object with multiple dbc.Col’s inside containing the graphs.
